## Notes

- Status legend: ⬜ Not Run · ✅ Pass · ❌ Fail
- **TC-06:** While verifying password hashing via DB Browser, leftover test rows from TC-02 found with empty data fields. Cleared with `DELETE FROM users;`.
**TC-07:** During validation testing, the max-length password test appeared to fail due to the client-side `maxlength` attribute preventing input of more than 14 characters. Temporarily removed the attribute, confirmed backend validation works, then restored it.
- **TC-11:** Username's leading/trailing whitespace is now trimmed via `.strip()` before the character-restriction check (from BUG-05) runs, so a padded username like `" jbwalk4 "` is trimmed to `jbwalk4` and passes validation. Before the whitespace fix, a space-padded username was rejected in initial testing by the character-restriction regex rather than by trimming logic. The end result looked correct, but for the wrong reason. Confirmed the two validations now work together correctly, in the intended order (trim first, then validate characters).
